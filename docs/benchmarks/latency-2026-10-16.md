# Stem latency profiling, 16 October 2026

The worker does not yet meet the 4.095-second hop p99 target reliably on the
primary laptop. With a temporary performance power profile, the final untraced
OpenGL run reached 9.182 seconds while Vulkan reached 2.199 seconds. An earlier
traced OpenGL run passed at 2.201 seconds. CPU waiting is reduced, but occasional
graph stalls remain. M0 stays open; M1 has not started.

The native helper now blocks on the final Vulkan fence instead of polling it.
The supervisor also sets `OMP_WAIT_POLICY=PASSIVE` and `GOMP_SPINCOUNT=0` in the
Vulkan child's environment. CPU inference inherits the caller's environment.
These changes let idle CPU threads sleep while the integrated GPU runs; the
application and worker do not change system power policy. No graph arithmetic,
shaders, window geometry or overlap-add behavior changed.

The [reproduction instructions](../../tools/stems/README.md) cover both wait
variants, the profiler and the chunk benchmark. CMake verifies the pinned
Vulkan source hash and generates the blocking variant in the build directory;
the upstream checkout stays unchanged. [Build metadata](data/latency/build.json)
records source, binary, model and header hashes. The source is audio.cpp v0.9.2
at `0097d365a00b52a6991ad7618f0a04e8d2935e47`, compiled with GCC 16.2.1,
Release `-O3 -DNDEBUG`, Vulkan and OpenMP. The F16 HTDemucs model and license
sources are unchanged from the [initial report](stems-2026-10-16.md).

Profiling ran on the ThinkPad X1 Carbon Gen 9, i7-1185G7/Iris Xe, 16 GB RAM,
Arch Linux, Mesa 26.2.4-arch1.1 and Qt 6.12.0. Each experiment used a small
animated native Wayland window and a separate silent stereo PipeWire stream at
48 kHz/256 frames. No competing benchmark or build ran during inference.
Other desktop activity and driver caches were not isolated or reset.

Repeating one identical normalized 7.8-second window removes changing source
content and supervisor assembly from the experiment. All 120 outputs across
these four sequential runs had the same SHA-256. Their round trips diagnose
stalls; they are not output-hop delivery measurements.

The upstream-hybrid run spent 95.0% of its round-trip time inside the reported
graph phase. During zero-based request IDs 5–14, median graph time rose to
6.642 seconds as median sampled actual GPU frequency fell to 400 MHz. Earlier
IDs 1–4 had a 1.860-second median graph and 1350 MHz GPU median. Across requests,
graph time and per-request median GPU frequency had correlation −0.968.
The package PL1 clipping flag was asserted in 94.9% of slow-phase samples,
and remained asserted during recovery. This supports a clock/power limitation
as a source of spikes; the flag alone does not predict their duration.
The [Linux i915 definition](https://github.com/torvalds/linux/commit/fa68bff7cf27d83e0ca83c6388d6bc2ddc599905)
distinguishes PL1 frequency clipping from its thermal reason flag.

Source inspection also found CPU polling in the final fence wait and OpenMP
worker spin. [GNU libgomp](https://gcc.gnu.org/onlinedocs/gcc-16.1.0/libgomp/GOMP_005fSPINCOUNT.html)
documents zero default spinning with PASSIVE. The observed CPU totals fell
with blocking/PASSIVE, but these sequential runs did not hold clocks, power
profile or temperature constant. They do not isolate each change's latency
effect. `getrusage` covers all process threads around `separate_chunk()`,
including transforms; it is not a GPU-kernel or graph-only CPU measurement.
Graph time includes transfers, synchronization and driver work.

The promising 2.312-second identical-window result did not generalize to the
first full worker rerun. With blocking/PASSIVE/zero spin, 61 continuous hops
still produced p50/p95/p99 of 2.244/6.332/7.030 seconds, RTF 0.588 and a
4.660-second first delivery. Seek parity and all control checks passed.
Nineteen of 61 hops exceeded the target.
That failure is retained in [unpaced-opengl](data/latency/unpaced-opengl/).

A temporary 3.5-second dispatch-interval experiment also failed. All waiting
was included in hop service; after 49 of 61 hops its maximum was 8.903 seconds.
The run was intentionally interrupted before EOF, paced delivery or control
checks. Its [raw evidence and interruption record](data/latency/rejected-cadence/)
remain, but the dispatch-interval implementation was removed. The older
harness saved cleanup reports without an interruption status; both benchmark
tools now save `status: interrupted` and return 130 on keyboard interruption.

During that experiment, `powerprofilesctl get` reported `power-saver`, firmware
profile was `low-power`, and CPU energy preference was `power`. Earlier runs
captured only the `powersave` governor, so their exact desktop profile cannot
be reconstructed. The governor remains `powersave` even under the performance
hold. New reports capture firmware profile and CPU energy preference at both
endpoints; optional traces record them throughout.

The final runs used `powerprofilesctl launch --profile performance` around each
benchmark command. AC was online; firmware profile and CPU energy preference
were `performance`. The hold affects the whole laptop, lasts only for the
command and was released afterward. Each run restored `power-saver` and left
no holds. The
[OpenGL](data/latency/performance-opengl/after-run-power.json) and
[Vulkan](data/latency/performance-vulkan/after-run-power.json) post-run snapshots
also confirm restored `low-power` firmware and `power` CPU energy preference.

Every complete chunk run used the same 15,491,445-frame synthetic fixture,
351.280 seconds at 44.1 kHz, delivering 60 full 5.85-second hops and the final
12,345-frame tail. Hop service includes source read/conversion, IPC, native
processing, reconstruction and overlap-add. It excludes initial source
preparation and waiting on a full output queue. First delivery includes source
preparation, model startup and benchmark consumption.

All three performance-profile runs passed exact forward/backward seek parity,
latest-control bursts, source replacement, held-result rejection, active and
backpressured cancellation, and hard shutdown. Each loaded the backend once,
discarded six superseded requests, bounded ready output to two hops and
delivered zero stale chunks. Logical cancellation does not preempt the GPU.
Both untraced paced tests had zero late-ready handoffs across five intervals
(29.25 seconds); their six hops were not played through PipeWire.

The late OpenGL spike was request 49: 9.091 seconds in the graph, 143.125 ms of
native inference CPU time, 4.954 ms of source read and 17.865 ms of overlap-add.
Graph rebuild time was zero. A [post-spike snapshot](data/latency/performance-opengl/late-policy.json)
40.312 seconds after that chunk still showed the performance hold, performance
firmware/EPP settings and a 400 MHz actual GPU clock. It did not sample the
failed graph itself, so the exact cause of this isolated stall remains unknown.

All three performance-profile runs' continuous-output hashes match both
historical OpenGL and Vulkan runs exactly. Recombination RMS remains
0.0020978 and the maximum per-stem join step remains 0.0794584 on this synthetic
fixture. These
numbers and seek parity verify retained arithmetic and assembly, not musical
quality or inaudible seams.

The untraced OpenGL/Vulkan audio probes ran for 204.988/194.590 seconds.
Both reported zero deadline misses, missing/invalid buffers, truncated frames,
observed graph-position discontinuities and observed clock recovery flags.
Callback p99.9 upper bounds were 20/18 µs; maxima were 161.947/53.922 µs.
These counters do not establish physical latency or complete graph xrun
coverage. The native Wayland windows confirmed graphics APIs 3/5 and completed
12,113/11,661 frame swaps. Swap counts do not measure interaction latency or
worst frame stalls.

Across all untraced scenarios, native VmHWM was 281,224 kB with OpenGL and
281,204 kB with Vulkan; peak VmRSS had the same values. Supervisor VmHWM was
197,416/196,504 kB for OpenGL/Vulkan. Sampled native CPU time
was 8.78/8.29 seconds; supervisor CPU time was 7.47/6.51 seconds. CPU totals
span the first through last successful sample. Supervisor memory includes the
benchmark and reference hops.

The traced performance run passed despite observed thermal pressure. During
continuous delivery, sampled package temperature reached 100 °C, the GPU
thermal reason flag appeared in 7.47% of samples, and CPU0 core/package thermal
throttle counters rose by 664/3435. GPU actual frequency had a 1300 MHz median;
PL1 was unasserted in those samples. Inference used 5.128 CPU seconds over
120.395 wall seconds, and the graph phase occupied 96.97% of hop service.
This short run does not validate sustained thermal behavior.

System traces are roughly 100 ms sysfs/proc snapshots, not per-kernel GPU
timestamps. `sched_schedstats` was disabled in the traced performance run, so
low schedstat wait values cannot rule out scheduling contention. It was not
recorded in the earlier profiles. RAPL energy reads were denied; no package
power in watts was measured. CPU throttle counters may be duplicated across
siblings. DRM allocation maxima overlap with each other and process memory;
they must not be added as a shared-memory peak. Raw errors and kernel units
remain in the JSON. Compressed traces retain deterministic gzip encoding and
uncompressed SHA-256 metadata.

The native helper built and ran both fence variants on Iris Xe. The application
build, all three CTest suites, 16 model-free worker cases and offscreen QML
rendering pass. The added process test verifies Vulkan-only OpenMP policy,
CPU inheritance, opt-out and parent-environment isolation. Temporary mock
checks also passed interruption cleanup/status/exit 130, incomplete-trace
rejection/exit 1, and string/schedstats metadata retention. CI exercises the
model-free application path; these laptop runs exercise the optional Vulkan
separator. README layout, the brand pack and LICENSE remain unchanged.

The probes exercise a small UI and independent silent audio output. They do
not route worker stems to PipeWire or implement the full deck workload.
Annotated music/listening, audible seams, physical output latency and a
60-minute full-workload thermal soak remain pending. No packages were
installed, global PipeWire settings changed, or model/API charges incurred.
Apollo was not used. M1 remains unstarted.
