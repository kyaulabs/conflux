# Publisher-default whole-track key screen

The publisher-default Winterreise Key-CNN method matched **11/24 selected tracks
(45.83%)** on each host, or **11/23 decoded tracks (47.83%)**. The unchanged MP3
rejection remains in the denominator. All 23 global decisions match the earlier
dense-window screen; switching to this whole-track recipe did not improve this
sample. The stock KeyFinder screen had matched 12/24 selections. These results
do not justify enabling automatic key detection.

This is the same fixed independent-artist selection used in the
[earlier screen](independent-keycnn-2026-10-29.md), with its reference labels and
results already exposed. It does not establish independence from upstream
training, local key-change accuracy or confidence calibration. The largest raw
mean assigned to an incorrect result was 0.784247. No threshold was fitted;
confidence remains Unknown and the production key backend remains disabled.

The frozen recipe uses the same checkpoint, legacy CQT and numeric forward path.
It follows the publisher's [60-frame, hop-30 global contexts without edge
padding](https://github.com/hendriks73/key-cnn/blob/9715d6f443c0f01d9842e567a3f20c9b228c3c7f/keycnn/feature.py)
and [float32 posterior average with first argmax](https://github.com/hendriks73/key-cnn/blob/9715d6f443c0f01d9842e567a3f20c9b228c3c7f/keycnn/classifier.py).
Short input receives the publisher's required right padding. Global normalization
precedes numerical batching. The separate float64 audit changed no decision.
No local key map is emitted.

Nineteen generated checks passed per host. They cover scalar window markers,
short-input padding, preservation of float64 features, whole-population
normalization, mean/argmax semantics, malformed results and owned pipeline
failure/timeout cleanup. Initial setup failures are retained: a resolved Python
path lost the virtual environment; supervisor hash checks needed Python 3.11+;
and one generated bytecode cache changed. The cache was restored from the pinned
read-only snapshot, and later children disabled bytecode writes. Runtime and
operation hashes matched at entry and exit of the actual music captures.

All 23 cross-host decisions agree. The largest raw posterior difference was
1.5497207642e-6, with zero elements outside the inherited 2e-6 absolute plus
2e-6 relative comparison bound. That bound is a descriptive numerical audit,
not a new qualification gate. The scoring contract was recorded after capture
started; inference settings were frozen before launch. Both units, their
original control groups and the private container were retired before scoring.

The [evidence manifest](data/publisher-key-2026-10-29/manifest.json) maps unique
gzip text members and byte-identical aliases to the plans, checks, failures,
captures, source metadata and scores. Publisher source files and weights remain
external, with their original commit and hashes recorded. No source audio,
model weights, binary arrays, runtime binaries or generated bytecode are redistributed.

These were CPU correctness captures. No player, hardware audio output or GPU
started, and no sync service, power policy, thermal rule, Best-quality stem
setting or milestone gate changed. M2's primary-laptop p99 target remains below
4.095 seconds; M2, M3 and the first release remain open.
