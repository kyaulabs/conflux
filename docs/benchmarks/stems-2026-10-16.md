# Laptop stem feasibility, 16 October 2026

HTDemucs through audio.cpp's Vulkan backend is a useful candidate for the next
worker experiment. It completed four-stem separation on the primary ThinkPad's
Iris Xe. This preliminary result does not pass the live-stem acceptance gate:
the tested interface is offline, and there is no bounded live adapter yet.
The application does not depend on this runtime or ship its weights.

The subsequent [persistent-worker measurements](worker-2026-10-16.md) test
contiguous chunk delivery, seeks and cancellation. Results below remain the
earlier offline CLI baseline.

The laptop is a ThinkPad X1 Carbon Gen 9 with an i7-1185G7, approximately 16 GB
RAM and Intel Iris Xe TGL GT2. The host Vulkan probe reported API 1.4.354,
Mesa 26.2.4-arch1.1, and the runtime reported FP16 support, no BF16, no integer
dot product, no matrix cores and 49,152 bytes of shared workgroup memory.
The sandbox hides `/dev/dri`; GPU runs used approved host device access.

All runs used four worker threads, the same F16 artifact and deterministic
44.1 kHz stereo PCM16 generated by
[`tools/benchmarks/stems.py`](../../tools/benchmarks/stems.py). CPU execution
expanded weights to F32; Vulkan retained F16. The model uses 7.8-second
segments, a 5.85-second hop and triangular overlap. A 5.85-second input produces
one centered, padded segment; a 23.4-second input produces four overlapping
segments. The fixture contains tones, a synthetic kick and seeded noise.
It provides reproducible processing load, not musical-quality evidence.

RTF is processing time divided by output duration; lower is faster.
Process completion includes startup, loading, decode, processing, WAV writes,
teardown and up to 20 ms of wait polling. It excludes fixture generation.
Single-file runtime timing includes `prepare()` and `run()`; batch item timing
includes `run()` only. Both exclude WAV decode, model/session construction and
output serialization. Graph timing includes synchronized device computation
and transfers. The four-chunk Vulkan run spent 7.129 s in that graph path.
No timestamp to the first usable streaming hop was measured.

The ten-item batch is a warm-request proxy. Its independent padded clips do
not reproduce contiguous streaming boundaries. It decodes the batch before
request timing and retains results, so its RSS includes retained material.
The reported percentiles use nearest rank with only ten samples; p95 and p99
are the observed maximum. They cannot establish a tail-latency guarantee or
the 60-minute thermal target. The 70% headroom target is 4.095 s per 5.85 s
hop; the warm proxy is promising, while CPU separation misses this budget.

RSS is the Linux process high-water mark, not total GPU/shared-memory usage.
The runtime reported an 80.309 MiB Vulkan weight buffer and 160.065 MiB CPU
weight buffer. Peak total GPU/shared allocation was not measured. Reported
virtual size is not physical memory consumption.

The Vulkan Qt/audio workload fully contained separator execution from
`2026-10-16T07:30:37.475717Z` to approximately `07:30:45.441083Z`.
The [UI report](data/ui-vulkan-contention.json) records 2,720 frames in 45 s;
the [audio report](data/audio-vulkan-contention.json) records 8,454 callbacks,
p99.9 at most 22 microseconds, maximum 31.555 microseconds and no reported
faults. This is one eight-second inference overlap with a small animated
window and silent stereo probe. It does not exercise decks, cue, recording,
effects, a full performance UI or long-run thermal behavior.

The same separator request with Qt's default OpenGL renderer ran from
`2026-10-16T07:31:49.732799Z` to approximately `07:31:59.467278Z`, fully inside
the [OpenGL UI interval](data/ui-opengl-contention.json) and
[audio interval](data/audio-opengl-contention.json). The UI completed 1,813
frames in 30 s. Audio reported 5,621 callbacks, p99.9 at most 40 microseconds,
maximum 82.545 microseconds and no faults. Both UI backends remained active;
one short comparison does not justify selecting the application's renderer.

Every emitted WAV was checked for four named stems per request, stereo,
44.1 kHz, PCM16 and the exact source frame count. The short CPU/Vulkan
recombination RMS errors were 0.002664 and 0.002645 relative to full scale.
Per-stem CPU/Vulkan RMS differences ranged from 0.000031 to 0.000196.
These checks detect gross output/alignment failures; they do not establish
separation quality, phase tolerance, listening quality or chunk-seam quality.
[Raw results and logs](data/stems/) retain the commands, hashes and measurements.

The exact graph executed on Vulkan without an unsupported-operator failure.
The inspected implementation dispatches the graph to one backend; it has no
automatic CPU operator fallback in the HTDemucs path. STFT, normalization,
iSTFT and overlap remain on the host. Vulkan kernels cover the graph's
convolution, transpose-convolution, matrix multiplication, normalization,
softmax and elementwise work, subject to dtype/layout limits. The graph uses
explicit attention on Vulkan; the fused attention branch is CUDA-only.
This establishes execution of this artifact, not general HTDemucs export or
operator support across other models and runtimes.

[ncnn](https://github.com/Tencent/ncnn/wiki/FAQ-ncnn-vulkan) remains an export
candidate and documents automatic CPU fallback for unsupported Vulkan layers.
[Native ONNX Runtime WebGPU](https://onnxruntime.ai/docs/execution-providers/WebGPU-ExecutionProvider.html)
uses Dawn/Vulkan on Linux and requires its own build and graph validation.
Neither model/runtime pair was exported or benchmarked in this slice. Keep
the runtime choice provisional until quality, chunk boundaries, seeks,
cancellation, resource limits and sustained UI/audio contention are tested.

Reproduce the measured binary path without installing it system-wide:

```sh
mkdir -p /tmp/conflux-stems/release /tmp/conflux-stems/models
curl -fL https://github.com/0xShug0/audio.cpp/releases/download/v0.9.2/audio-v0.9.2-bin-ubuntu-x64-vulkan.tar.gz \
  -o /tmp/conflux-stems/runtime.tar.gz
curl -fL https://huggingface.co/audio-cpp/audio.cpp-gguf/resolve/f861648c0c1f4da9f18e9a0ce5e217b0679bb2f5/HTDemucs-GGUF/htdemucs-f16.gguf \
  -o /tmp/conflux-stems/models/htdemucs-f16.gguf
sha256sum /tmp/conflux-stems/runtime.tar.gz /tmp/conflux-stems/models/htdemucs-f16.gguf
# Compare both hashes with the artifact table before execution.
tar -xzf /tmp/conflux-stems/runtime.tar.gz -C /tmp/conflux-stems/release
python3 tools/benchmarks/stems.py \
  --cli /tmp/conflux-stems/release/audiocpp_cli \
  --model /tmp/conflux-stems/models/htdemucs-f16.gguf \
  --backend cpu --output /tmp/conflux-stems/cpu
python3 tools/benchmarks/stems.py \
  --cli /tmp/conflux-stems/release/audiocpp_cli \
  --model /tmp/conflux-stems/models/htdemucs-f16.gguf \
  --backend vulkan --output /tmp/conflux-stems/vulkan
```

Each output directory must be new or empty. Use `--batch-hops 10` for the
warm-session proxy, or `--seconds 23.4` for the four-chunk request. Run GPU
commands where the device is accessible. Keep downloaded binaries, models,
fixtures and stems outside source history.
