# M0 balanced-policy comparison, 16 October 2026

The laptop completed another 3,600.0003-second audio/UI soak under `balanced`.
The 4.095-second continuous-hop p99 target still failed: **6.128 seconds p99,
14.888 seconds maximum and 202/1,258 misses (16.06%)**. All eleven
cancellation/seek checks passed, output hashes matched the performance trial,
and the independent silent audio probe recorded zero observed faults. Balanced
selection alone does not establish reliable delivery. M0 remains open and M1
has not started.

The [performance-profile hour](thermal-2026-10-16.md) is the reference. Runtime,
model, fixture, worker, soak, sampler, UI and audio binary hashes are identical.
The same persistent Vulkan backend, four native threads, blocking fence wait,
PASSIVE/zero-spin OpenMP policy, 7.8-second window and 5.85-second output hop
remain in use. Both hours saturate delivery, check cancellation/seeks every
five minutes, sample native/system state every 0.5 seconds, and use the same
small animated Wayland/OpenGL window and silent 48 kHz/256-frame PipeWire probe.
No inference implementation or global driver/desktop configuration changed.

Balanced delivered 1,269 chunks including eleven first chunks after seeks.
The all-delivered set has 204 misses; its p99 and maximum match the continuous
subset. All twelve complete five-minute continuous bins failed p99. The
all-delivered first/last five-minute p99 values were 4.633/6.933 seconds.
Nearest-rank percentiles describe these finite, correlated repeated-window
observations; they do not establish a future tail bound.

This is a sequential comparison on the same laptop, with other desktop
activity present. Starting temperatures and available memory were recorded,
not held equal. Before the balanced wrapper, the package snapshot was 48 °C;
the soak's initial condition report was 75 °C and its first native sample was
60 °C. The corresponding performance initial report/first native sample were
87/80 °C. These are distinct timestamps, not interchangeable starting values.
The comparison does not attribute every difference to power policy alone.
Across the balanced workload, package samples ranged from 55 to 78 °C and the
other recorded CPU thermal zone from 47.05 to 73.05 °C.

All 7,057 balanced native snapshots reported firmware `balanced` and CPU EPP
`balance_performance`, with no missing or deviating samples. All seventy running
monitor snapshots reported balanced with no holds. This daemon does not support
a balanced hold, so a scoped runner selected balanced temporarily and restored
the previous profile afterward. It preserves a different intervening profile
selection rather than overwriting it.

The balanced misses do not require the performance run's 100 MHz phase. Across
all 204 delivered misses, median actual GPU clocks ranged from 350 to 650 MHz,
while requested medians were 1350 MHz. PL1 was asserted in 78–100% of each
miss's snapshots. No GPU thermal flag was observed within these miss interiors.
These are snapshot summaries, not elapsed-time-weighted fractions or proof
that PL1 caused each delay.

The worst request, 1126, took 14.888 seconds, including 14.408 seconds in the
graph and 392.198 ms native CPU time. Ready-queue delay was 0.251 ms and no graph
rebuild occurred. Identical-window requests before/after completed in
2.178/2.220 seconds with identical output hashes. The slow request's sampled
actual GPU median was 350 MHz, render accounting covered 40.96% of its strict
interior span, RC6 increased by 100 ms and runtime-suspended time did not
increase. Package temperature stayed at 57–60 °C. Thus neither 100 MHz nor a
high instantaneous package temperature is necessary for a long delay.

The worst request also overlapped 9.851 ms of memory PSI, 3,583 pages of
background reclaim and 179 pages swapped in. This is concurrent memory activity,
not an observed fourteen-second host PSI stall. It does not exclude all
driver/GEM memory paths. The common finding remains lower actual GPU clocks
and PL1 assertions with partial engine accounting; the firmware/platform-power
versus driver trigger is unresolved.
The accessible kernel graphics journal had no matching entries for the bounded
hour interval. This does not rule out unreported driver events; root-only error
state and tracefs diagnostics remain unavailable. Scheduler wait statistics
were disabled, so they cannot exclude scheduling contention.

All eleven controls completed with zero stale chunks and exact trimmed seek
parity. Nine checks invalidated a current held chunk; two held chunks were
already obsolete. The harness cancels at least 150 ms after a matching
supervisor start event and rechecks request/generation identity. It does not
observe GPU submission or preempt active Vulkan work. The scheduled drain
measurements do not bound cancellation during every stall. Hard shutdown with
work in flight took 215.248 ms. One backend stayed loaded, ready-queue high-water
was one against a limit of two, and no telemetry was dropped. There were 1,249
same-grid hash checks, eleven trimmed checks and 128 full source loops.

Audio covered the entire 3,600.0003-second workload intersection. Its 675,297
callbacks rendered 172,876,032 frames at negotiated 48 kHz stereo and a fixed
256-frame quantum. Callback p99.9 was at most 21 µs and maximum execution was
167.559 µs. All six observed fault counters were zero. These measurements cover
callback execution and reported graph clocks, not physical speaker latency or
a complete graph xrun count; separated stems were not played.

The UI reported 215,522 GUI-thread frame notifications, sixty nonzero complete
minute bins and a 109.564 ms maximum notification gap. No sampled exposure loss
occurred. The frame/heartbeat/scene-graph gate passed. This establishes the
small M0 animation workload, not physical presentation latency or full-deck
performance.

Native RSS/HWM peaked at 281,192 kB; supervisor RSS/HWM at 159,436/165,160 kB.
Both reported zero process swap. Observed native/supervisor CPU time was
223.97/132.75 seconds between successful first/last samples. The largest sample
gap was 607.630 ms; median/maximum capture time was 8.904/83.576 ms. RAPL energy
reads were denied; native/supervisor fdinfo errors were 3/7,189 and remain
explicit. Missing fields are not substituted with zero. RSS and DRM maxima
must not be added as a shared-memory peak.

The unchanged UI guard restored/unloaded its owned-window policy and released
the idle inhibitor. The runner restored `power-saver`, firmware `low-power` and
EPP `power`, with no holds. Generated fixture WAVs were removed. Review caught
equal nested shutdown deadlines before the hour: the copied balanced runner
now allows five seconds for graceful child stop and two for forced-stop wait,
with two-second power-command timeouts. Configured cleanup waits total at most
seventeen seconds, excluding local overhead, below the outer twenty-second
guard deadline. Nine mocked error/cancellation paths passed. A real interrupted
GPU/audio/UI preflight exited its owned native/UI processes, removed its fixture,
restored power policy and released the guards in 1.969 seconds.

Raw measurements, wrapper lifecycle records, exact source pins, compressed
traces and independent analyses are retained in
[the policy evidence archive](data/policy/manifest.json). The 120-second
balanced preflight passed before the hour; its original wrapper is retained
separately from the corrected hour wrapper. No model weights, binaries or
generated audio are committed.

Because balanced failed, the next experiment replayed the worst window directly
through one persistent native process. The new
[`native_replay.py`](../../tools/benchmarks/native_replay.py) diagnostic uses
the same fixture and whole-source normalization, window start 773,955 (three
hops), frozen runtime/model and native execution policy. A CPU-only check
compared it with the actual worker source/window methods: all 2,751,840 input
bytes matched, SHA-256
`88eda258fb0ca3a51c7df89b58d6ab20d2c3a3c46d34eb6da5a4b1ffed0c8672`.
It starts no worker supervisor, audio probe or benchmark UI, and performs no
seeks or cancellation. The existing desktop still runs; this is not exclusive
use of the machine or GPU.

A three-request host preflight passed before the full replay. The full replay
completed 120 serial requests in 244.400 seconds under balanced, with no errors
or requests above 4.095 seconds. All native output hashes were identical.

The native replay's actual/requested GPU sample medians were 1100/1350 MHz.
PL1 was asserted in 450/482 workload snapshots (93.36%) despite zero misses,
so PL1 alone is insufficient to identify a stall. Render accounting covered
90.70% of the strict workload interior, versus 40.96% in the balanced worst
request. RC6 advanced 8.548 seconds across the replay; runtime-suspended time
did not increase. Package samples were 59–74 °C, with no GPU thermal flag.
Native RSS/HWM peaked at 281,304 kB with zero observed process swap. No graph
rebuild occurred. All 483 native snapshots retained balanced/EPP settings. The
trace had no sample/write errors; denied RAPL reads remain explicit. These are
sampled associations, not a causal model.

The long stall did not recur in this bounded native replay. Its shorter duration,
fixed window, different starting heat/memory and absent audio/UI/control workload
prevent attributing the difference to a particular removed component. Native
round trips also omit output-hop assembly and delivery. This is diagnostic
non-recurrence, not a passing replacement for the failed hour or a verified
remedy. Both native trials removed the generated WAV, closed their native child
and restored the lifecycle's prior `power-saver` profile with no holds. Their
normalized input remains only in ignored local output. The pre-smoke sandbox
snapshot is qualified separately; host lifecycle records govern profile claims.

Independent audits recomputed the balanced and native distributions, control
timings, audio/UI coverage and policy samples, and checked producer/input/output
pins, recorded runtime parity assertions and repeated hashes. Seek waveforms
are not archived for independent numerical recomputation. Reanalysis from the
compressed balanced archive reproduced every numeric
measurement and join. CPU-only normalization checks, nine mocked runner paths,
the real interrupted preflight, native syntax checks and the required frozen
pnpm install passed. The production worker, UI, audio code and binaries are
unchanged in this comparison.

M0 remains open. The [load-isolation follow-up](load-isolation-2026-10-16.md)
preserves sustained diagnostic failures and a completed audio/UI hour under
the unchanged host thermal guard. The [remaining isolated hours](load-isolation-resumed-2026-10-16.md)
subsequently completed, with worker-only and audio-only p99 passing and UI-only
p99 failing the target. No global driver synchronization workaround or inference
change is justified by these observations. Musical quality/seam checks, stem
routing, physical audio latency and full-deck load remain unverified. M1 has
not started.
