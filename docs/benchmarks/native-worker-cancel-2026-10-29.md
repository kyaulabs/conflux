# Native worker hard-cancellation check

The bounded silent check passed on the laptop and Apollo. After the native process read its request input and before output publication, `StemWorker.close(timeout=0)` killed and reaped the actual Vulkan runtime in **34.556 ms on the laptop** and **69.739 ms on Apollo**. Neither published a partial chunk.

Both probes used the pinned Best-quality model/runtime and the unchanged production `StemWorker`/`NativeRuntime` implementation. Each sent one request from 64 generated stereo frames padded by the normal worker window path. Runtime readiness bound the requested Vulkan backend, two CPU threads, model identity and process ID. The laptop reported Intel Iris Xe; Apollo reported its NVIDIA device. This was not a latency, audio-output or listening test.

The trigger was `IN_CLOSE_NOWRITE` for `input.f32` in a new private native spool. The probe also required the current generation/request to remain in flight, no ready chunk, no output file, a live pinned child and the complete expected input extent. inotify supplies no reader PID; attribution relies on the cooperative same-user scope and the pinned child being the only reader of this new spool. Input consumption does not prove an active GPU fence. The capture therefore does not qualify GPU-fence preemption or full-player shutdown.

On each host, the native return code was `-9`, its pidfd became readable, the process was reaped, the supervisor thread stopped, the native spool disappeared and the ready queue was empty. The normal error event caused by forced child termination is retained; it is not a partial audio result. The generated offline checks cover this boundary, premature output, observation loss, owned cleanup, declined/stale readiness and dispatch ownership. All 25 existing checks per host passed before the frozen packet was armed; they do not replace the actual-model captures.

Both hosts dispatched concurrently under the original five-minute operator deadline. The laptop first completed its guarded settling interval and stayed within its existing cap ceilings. No power profile, cap, thermal-guard policy, OneDrive state or global audio configuration changed. Independent readback confirms both exact units and their original cgroups are gone and the dedicated Apollo daemon has no container. No automatic retry occurred and no controlled test remains active.

The [summary](data/native-worker-cancel-2026-10-29/summary.json) and [manifest](data/native-worker-cancel-2026-10-29/manifest.json) retain the raw component results, terminal ownership proof, fixed packet and original tests. This establishes forced cleanup at the consumed-input boundary; remaining cancellation coverage and other M2/M3 requirements remain open.
