# MPEG length estimates and clean EOF

CONFLUX now prepares MPEG audio to the decoder's clean end of file instead of
requiring its opening length estimate to match every decoded frame. Real
decoder errors, nonfinite samples, cancellation and the actual PCM byte budget
remain checked. Formats with exact frame counts and declared raw stem output
retain their strict extent checks.

The new FMAK key-analysis sample exposed the problem before any model ran.
Of 24 fixed, distinct-artist selections, six native preparations failed, one
completed and seventeen were interrupted or not run when the batch was stopped.
Those results are retained; there is no key-accuracy result from this attempt.
The stopped unit and its process group are absent, its spools are retired and
all seventy frozen input pins still match. The parent initially reported
incomplete cleanup because the operator had already retired its invocation;
a separate verification records the actual closed state without replacing that
failed receipt.

For FMAK track 013088, the installed decoder reported 7,250,594 source frames
but delivered 7,243,776 at 44.1 kHz, then clean EOF with no decoder error. Its
opening count exceeded the actual audio by 6,818 frames. The unchanged preparer
rejected it. The patched preparer produced **7,884,382 stereo frames at 48 kHz**,
within one frame of the conversion ratio for the actual decoded source. Its
PCM SHA-256 and unchanged source identity are retained in the
[evidence manifest](data/m2-mpeg-length-2026-10-27/manifest.json).
No source audio or prepared PCM is included in the repository.

The [mpg123 API](https://www.mpg123.org/api/group__mpg123__status.shtml) documents
that its length query can estimate from file size when neither an Info frame
nor a scan is available. The installed libsndfile 1.2.2
[MPEG decoder](https://github.com/libsndfile/libsndfile/blob/1.2.2/src/mpeg_decode.c#L192)
uses that query for `SF_INFO.frames`. Its
[read API](https://libsndfile.github.io/libsndfile/api.html) returns partial or
zero reads at EOF without requiring an error.

The new regression failed before the production change and passed afterward.
It wraps only the returned codec length/format metadata while retaining real
decoding, then checks complete samples and channels for overestimated,
underestimated and unknown counts at 44.1/48 kHz, mono/stereo. Both memory and
disk-backed outputs match the exact-length baseline; a one-frame-smaller PCM
budget still rejects the output. Exact-length short reads and explicit decoder
errors remain rejected. The existing audio-file, audio-preparation and
audio-level tests also passed: **four CTest cases, zero failures**.

This is an offline preparation correction. No audio device, model, GPU worker
or player started. The corpus remains unscored and its song-level tags cannot
establish local key-change accuracy. The last actual-player result remains
**8.889-second p99** against the unchanged **4.095-second target**. Best quality,
the 15 W ceiling, thermal guard and M2/M3/0.1.0 release gates remain unchanged.
