# M3 performance controls

M3 is in progress. On 21 October 2026, the user authorized manual mixing
controls in parallel with M2. M2 remains open at Best quality with the unchanged
4.095-second live-stem service p99 target. The latest instrumented player
sample reached 4.543 seconds; it does not qualify normal latency.
See the [retained results](benchmarks/player-attention-profile-2026-10-21.md).

The A/B crossfader uses fixed assignment, A at the left and B at the right.
Center preserves both channel levels at unity. Moving left attenuates B;
moving right attenuates A. Each send ramps over 240 frames (5 ms) in the live
session. The master output and recording include these sends. Headphone cue,
pre-fader deck meters, channel/stem targets and source clocks remain independent.
Muted decks continue advancing.

The crossfader accepts pointer and keyboard input and follows acknowledged
engine state. It requires ready audio output and remains available during
individual deck replacement. Source swaps and output-session reconstruction
retain its position. See the [control inventory](cdj-controls.md) for the
current interface and inactive controls.

Manual IN/OUT/RELOOP operates on prepared normal audio and four-stem banks.
IN captures the render cursor and asynchronously retains up to 64 seconds of
unchanged PCM. OUT requires ready cache and a span of at least 256 frames
(5.33 ms), then repeats the half-open IN–OUT interval. EXIT completes the current
segment and continues past OUT. RELOOP starts at IN again. A single existing
stem gain-ramp state serves cached and linear reads; the original reader and
any aligned surplus remain parked at OUT during repetition.

Each playback owner retains at most 23.44 MiB for a normal loop or 93.75 MiB
for four stems, plus small worker/control storage. Pending cache construction
replaces the previous allocation after its last render borrow; retirement and
shutdown join the worker off callback. Status reports the actual resident bytes.
A failed optional cache leaves healthy linear playback available. RELOOP after
linear playback has continued repositions the OUT continuation once; an immediate
EXIT can report buffering while that continuation refills.

Pause/resume retains loops. Explicit seek, jog, transport CUE, retry, replacement
and output-session reconstruction clear them. The controls follow acknowledged
engine state and stay unavailable for live stems, temporary CUE preview, read
errors or an unavailable/replacing deck. These are unquantized manual loops;
4/8-beat loops, beat jump and loop-point editing remain unavailable. Set IN again
to define another loop.

Prepared stereo tracks and aligned four-stem banks now support a fixed ±6%
tempo range. Without Master Tempo, libsamplerate's best sinc converter changes
speed and pitch together. Master Tempo uses Rubber Band's finer R3 real-time
engine, with default windowing and no internal worker threads. The user accepted
the fixed −6%/+6% listening previews for Club XL and When the Light Breaks:
“Master Tempo sounds acceptable.” This accepts preview sound; dynamic player
transitions and laptop mixing still require testing. Rubber Band 3.3+ is a new
build dependency because the existing sample-rate converter cannot preserve
pitch independently. Its GPL-2.0-or-later library is used by this AGPL project.

Each prepared owner has one separate processing worker with duplicated raw-file
descriptors. File reads, finite/identity checks, DSP setup and processing happen
off callback. Eight fixed output slots retain at most 256 KiB of raw four-stem
PCM per owner; this is queue payload, excluding processor, staging and existing
reader/cache memory. Current render-side stem gains mix those raw leaves through
the same gain-ramp state as normal playback. The callback only publishes fixed
requests and consumes a bounded queued prefix. Underflow reports buffering,
holds that deck's source position and lets the peer and output clock continue.

Speed requests in an active converter retain its state across zero. Zero in
that mode is still processed audio; TEMPO RESET explicitly restores the normal
read path at the captured cursor and retains the Master Tempo selection. A
key-lock change, seek, jog, transport CUE or retry starts a new generation;
stale PCM and failures cannot become current output. Pause stops consumption
while bounded prefetch may continue. The same whole owner retains its selected
mode across an output-session rebuild. If recovery must recreate a failed finite
owner, it restores the logical speed/key-lock settings with fresh processing
state. Loading a replacement track starts with original speed and Master Tempo
off. This first integration mutually gates manual
loops and tempo processing, including an active zero-percent converter. Clear a
stored loop with seek/CUE before starting tempo; reset tempo before using loops.
Their combined operation and live-stem tempo remain unfinished.

Processed source time is a fractional nominal transport cursor derived from
consumed output and input-configuration metadata, not an exact Rubber Band
per-sample source map or an immediate audible-ratio acknowledgement. It clamps
at the track end while every returned tail frame continues playing. Completion
requires consuming the separate final marker; an unavailable suffix is not EOF.
No nominal-duration cropping is applied. The CDJ tempo rail, Master Tempo
indicator, reset and pending/error status follow acknowledged engine state.

## BPM controls and window chrome

The tempo rail uses BPM: arrows change 0.1 BPM, Shift/arrows and Page keys
change 1 BPM, and down increases speed. Its range retains the existing six
percent speed limit around the original reference. Playback and the displayed
value follow the engine's acknowledged ratio. Master Tempo preserves pitch;
RESET returns to original speed and retains that selection.

Click the BPM display in either deck's LCD to enter an original BPM manually
or select **Use automatic**. Changing the reference does not change playback
speed. An override belongs to that deck's loaded source: same-content reloads
retain it, a different source clears it, and failed/cancelled replacement keeps
the previous value. Overrides are not saved across application restarts.

Automatic analysis runs in a cancellable CPU child during deck preparation,
using the original mix for normal and stem loads. It uses the pinned full
Beat This `final0` model, separate-channel linear-mel averaging, source-duration
masking before peak selection, and the median of adjacent source-frame BPM
estimates, rounded to one decimal. A usable result is labeled **Estimated**;
missing, failed or insufficient analysis leaves BPM unknown and allows manual
entry. A single reference summarizes the track; it does not describe a local
variable-tempo map or establish beat synchronization. The earlier detector
challenge passed 9 of 24 accuracy screens. That result remains unqualified,
and this control change does not close M2's musical-analysis or live-stem gates.

The worker accepts at most 256 MiB of stereo 48 kHz float PCM, a 180-second
deadline, an 8 GiB address-space limit and bounded output/diagnostics. The parent
checks retained PCM identity and content, result identity, cancellation and
owned-process cleanup. An ordinary analysis error leaves audio usable; corrupt
prepared PCM fails the load. Compositor checks remain separate from the
offscreen tests.

The analysis runtime is installed separately. The existing native audio path
does not need Python/Torch; learned analysis needs their pinned CPU environment
and local source/model assets. For Linux x86-64 with Python 3.12, the wheel hashes
are in [the runtime lock](../tools/timing/requirements.txt). Supply the unmodified
[Beat This source at the pinned commit](https://github.com/CPJKU/beat_this/tree/b95c8ab0c58c2d9fcfd40508ae8dffbc05ac4f5c)
with its MIT license and the published `final0` checkpoint (81,058,141 bytes,
SHA-256 `8c328b45f59d8dd3dff219253ff6a8d6482be57d0133a29140e2febbf8eb8331`).
The worker verifies its executed source files, dependency versions and checkpoint;
it never downloads weights while loading a track.

```sh
build/dev/conflux --bpm-python /absolute/venv/bin/python \
  --bpm-source /absolute/beat_this-source --bpm-model /absolute/final0.ckpt
```

Without these flags, CONFLUX looks for `bpm-runtime/venv/bin/python`,
`bpm-runtime/source` and `bpm-runtime/final0.ckpt` beneath its local application
data directory (normally `~/.local/share/conflux`). Missing runtime assets leave
automatic BPM unavailable. The installed worker lives in `share/conflux`; a
development build uses its adjacent copied worker.

CONFLUX owns its title bar, with the brand logo on the left and minimize,
maximize/restore and close buttons on the right. Drag its left header area to
move the window, double-click it to maximize/restore, or drag a window edge to
resize. These gestures request the compositor's normal system move/resize.

The local library has a **Browse** file chooser beside each deck path. Choosing
a file fills only that row and clears the saved-track selection; it does not
start preparation or replace a deck. **Add to library** prepares and saves the
track's library entry without loading it. **Load A/B** loads the selected saved
track or the chosen path onto that deck. Cancelling the chooser leaves the
current paths, saved selection and playback unchanged.
On Linux, normal graphical startup defaults to Qt's desktop-portal theme so the
chooser uses the desktop's system Open window. Explicit Qt theme selections and
headless test platforms retain their configuration. This requires the Qt portal
plugin, the session portal service and a desktop FileChooser backend.
