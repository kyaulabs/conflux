# M2 preparation and stems

M2 is in progress. Persistent source-audio preparation, cancellation and local
library import/list/load are implemented. Beat/phrase/key/cue analysis, cue
import, stem preparation/delivery and mixing controls remain unfinished. The
engine can mix an aligned prepared stem bank and retire it as one deck owner.
The promoted Flash
runtime passed the **4.095-second live-stem service p99** target during a
**60-minute independent-load run**, with about **70 ms** of continuous-hop p99
margin.
Integrated stem playback and fallback remain pending under the
[approved M0 decision](decisions/0002-m0-stem-runtime.md), so the M2 release gate
remains open. A prepared-PCM cache hit does not measure separation performance.

Loading a track prepares stereo 48 kHz float PCM and its waveform off the GUI
thread. The cache key includes the source SHA-256 and preparation recipe,
including decoder/converter versions, format and waveform settings. Reopening
an entry validates its manifest, PCM size, SHA-256, finite samples and waveform
through the retained read-only descriptor. Matching content can reuse an entry
across filenames; changed source content uses a different key.

Preparation hashes and decodes the same opened regular file, then checks its
identity, size, timestamps and content again before returning or publishing.
Complete PCM and metadata are staged and synchronized before publication.
Malformed regular entries are regenerated; unexpected files, symlinks and
FIFOs fail closed. These checks detect ordinary concurrent changes; they do not
provide a snapshot against malicious writes by the same user.

The manual player stores entries under Qt's application cache directory in
`prepared/v1`. On this laptop that is on ext4. Limits are 1 GiB of source
bytes, 256 MiB of prepared PCM per track, 64 entries, 16 KiB per manifest and
2 GiB of managed cache/preparation storage. Publication reserves room for the
anonymous candidate and staged copy as well as existing entries. A full cache
rejects further preparation; this slice does not evict existing tracks.
Filesystem page cache remains separate from the fixed reader buffers.

**CANCEL PREPARATION** remains available until the GUI accepts the result for
installation, including when worker completion is waiting in the event queue.
Cancellation leaves loaded-deck metadata and current playback intact. Loading
stays busy until candidate readers and descriptors are released. Once the
status becomes **Installing**, cancellation is unavailable. A result already
published before cancellation may remain cached for a later load.

The library drawer imports an absolute local-file path and lists saved tracks.
Select a saved row, then use **LOAD A** or **LOAD B**. Editing a path restores
direct loading. Filenames with Unicode, spaces, `#` and `%` retain their literal
meaning; displayed names use plain text. Timing and key analysis remain
unknown. Missing sources are marked from the last library read/import snapshot;
each load rechecks the actual source hash before installing audio. A changed
file must be imported again. Importing identical content at another path updates
its existing row; changed content at the same path replaces that row's identity.

Library metadata lives in `library.json` under Qt's application data directory,
outside the PCM cache. The versioned catalog is bounded to 1 MiB and 1,024
records. Writers lock, reread and merge before an atomic save with private file
permissions. Invalid, oversized, symlink or FIFO catalogs fail closed and remain
untouched. Their error remains visible while direct path loading stays usable.
Source preparation limits still apply to imports.

Import cancellation remains available through queued preparation completion.
The **Saving** phase commits the accepted catalog change and cannot be cancelled;
shutdown joins that write. Catalog startup reads and imports leave active
playback alone. Importing does not load either deck. Cue data and automatic
musical analysis are not populated by this slice.

Tests cover cold/reopened reuse, source changes, corrupt entries, unsafe file
types, storage bounds, concurrent publication and cancellation after a real
source read. Controller and QML tests exercise cancellation state, pointer and
keyboard controls, retained playback controls and installation cutoff. A
private virtual PipeWire check compares generated channel samples while the
peer deck prepares/cancels, verifies cached retry and exercises immediate
shutdown from completion notification. It uses no hardware output and makes
no latency or listening claim. See [testing and coverage](testing.md) for the
commands and measurement limits.
