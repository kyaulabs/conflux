# M1 manual audio foundation

M1 now has a Qt Quick window for two local-file decks, with file loading,
play/pause, seek, deck gain and master gain. The window and headless probe
use the same render core. The current view follows the CDJ-3000 deck layout
and central four-channel mixer arrangement in the [control inventory](cdj-controls.md).
M0 closed under the user's
[approved feasibility decision](decisions/0002-m0-stem-runtime.md). The failed
4.095-second live-stem service p99 target remains a mandatory M2 blocker before
a first usable release.

The decoder uses system libsndfile, already exercised by the earlier reuse
probe. The standard library has no audio decoder; using libsndfile keeps this
path independent of Qt. The laptop has version 1.2.2, with package license
`LGPL-2.1-or-later`. Install `libsndfile` on Arch or `libsndfile1-dev` on Ubuntu;
CI includes the development package.

The decoder accepts nonempty, regular local files with stereo 48 kHz audio.
It preloads at most 64 MiB of float PCM per deck, about 174.8 seconds each,
before opening the stream. Two decks therefore hold at most 128 MiB of PCM;
this limit excludes decoder overhead and other process memory. Unsupported
geometry, excessive decoded size, decoder errors and nonfinite samples fail
before playback. There is no resampling yet, so the earlier 44.1 kHz listening
files are not inputs to this path.

Each immutable PCM owner outlives the renderer and stream. The command-line
probe starts loaded decks playing; the manual window installs each new file
paused at frame zero and unity deck gain. Decks have independent source
positions and requested play/pause state.
Pause holds a deck's source position; seek preserves its play/pause state.
Each deck renders silence after EOF and clamps its source position there.
EOF does not change the playing request; seeking back resumes a deck whose
request is still playing. The output sample clock advances for every valid
output block, including silence, and does not reset on a source seek.

Deck and master gains are linear, finite values in [0,1], initially one.
The renderer sums the two float PCM signals using double intermediates for
gain products, addition and master scaling. Conversion back to float saturates
only outside the finite float range. Ordinary values above ±1 remain, so the
sum can clip downstream. There is no limiter, automatic normalization or
gain/transport ramp. Invalid deck indices, unloaded-deck commands, out-of-range
seeks and invalid gains leave renderer state unchanged.

Renderer state belongs to the render thread. A separate single-producer,
single-consumer `TransportQueue` holds 32 commands in fixed storage using
lock-free atomics. A full push or empty pop fails immediately. The control
loop enqueues commands; the callback drains at most 32 before rendering a
valid nonempty block and records bounded receipts. Reporting reads those receipts
after the stream stops. The callback does no decoding, file I/O, allocation
or locking.

```sh
cmake -S . -B build/dev -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build/dev --parallel 2
ctest --test-dir build/dev --output-on-failure
build/dev/conflux-audio-probe --input /path/to/deck-a-48000.wav \
  --input-b /path/to/deck-b-48000.wav --seconds 5 \
  --start-frame 0 --start-frame-b 0 --gain-a 0.5 --gain-b 0.5 \
  --master-gain 0.5 --controls /path/to/controls.txt
```

`--input` loads deck A; `--input-b` optionally adds deck B. Both `--input-b`
and `--controls` require deck A.
`--input` and `--tone` are exclusive. Without either, output remains silence.
Starting frames and deck gains require that deck's input. The report includes
each deck's decoded frames/bytes, decode time, initial/final source position,
requested playing state, gain and EOF. It also reports master gain, submitted/
applied/rejected commands and receipts at output-frame boundaries alongside
the existing callback and graph-position counters.

A control script is a regular local file of at most 16 KiB with at most 32
nonempty rows. For example, `controls.txt` can contain:

```text
0 a gain 0.5
500 b pause
1000 a seek 0
1500 b play
2000 master gain 0.5
```

Rows use `milliseconds a|b|master action [value]`. Deck actions are `play`,
`pause`, `seek` with a source-frame value, and `gain` with a value in [0,1].
The master accepts only `gain`. Times are nonnegative milliseconds from entry
to the streaming state, in nondecreasing order, and must precede the requested
`--seconds` duration. Extra fields and commands for unloaded decks are rejected
before PipeWire initialization. The main loop checks due rows every 100 ms;
the render thread applies queued actions at a following callback boundary.
Receipts identify that output frame. This is coarse wall-time scheduling,
without a sample-exact wall-time or click-free transport guarantee.
The probe fails if it stops before every planned action is applied; actions
near the stream's end can remain incomplete.

Run `build/dev/conflux` for the performance window. Select a deck's Browse
control or Library, enter an absolute local file path and select Load A/B. File decoding runs in one QtConcurrent
job while existing playback continues; a second load is rejected until that
job finishes. A decode error preserves both decks. Installing a successful
result stops and destroys the shared PipeWire stream before replacing the
borrowed PCM, then restores the other deck's exact stopped position, playing
request and gain. Accepted commands still queued at stop are applied before
that state is captured. The output interruption is intentional in this first
control slice; seamless replacement is not implemented. The new session's
output clock and telemetry counters start at zero. During replacement,
old and new owners can hold up to 192 MiB of decoded PCM in total.

The GUI never reads live renderer fields. A PipeWire thread loop consumes the
same 32-slot command queue and publishes fixed-size state snapshots through
a separate 32-slot queue. The GUI polls every 50 ms. When snapshot storage is
full, the callback drops telemetry and continues audio; later snapshots carry
cumulative state. Normal window playback has no 32-action lifetime limit.
The callback does no decoding, Qt calls, file I/O, allocation or locking.
Output readiness and errors are polled without blocking the GUI for a startup
wait. Closing stops audio before releasing PCM and waits for any running
regular-file decode job; this is orderly shutdown, not decoder cancellation.

The old M0 rendering window is preserved byte-for-byte as `qml/Harness.qml`
and selected by `--smoke-test`. Smoke mode creates no audio controller or
decoder worker. New binary hashes still identify the updated executable;
this compatibility does not make it the earlier pinned M0 binary.

The CDJ redraw replaces the card layout with same-orientation deck faces,
upper recessed displays, eight Hot Cue positions, large static jog displays,
left-side transport and right-side tempo rails. Four mixer strips sit between
the players, with active A/B channel faders and a master Dial. Library path
entry is in a drawer. Pending hardware functions are visibly inactive and
listed in Control Status; their presence does not mark M3 complete. The user
accepted this visual direction during the laptop preview.

Each decode job now computes at most 512 stereo peak buckets, normalized to
the source peak for display. This leaves the audio PCM unchanged. The overview
Canvas repaints only when its data, size or palette changes; the actual source
position uses a separate playhead. No BPM, key or beatgrid is invented.
