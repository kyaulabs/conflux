# M1 manual audio foundation

M1 has started with one decoded local file feeding the same render core used
by the PipeWire callback and headless tests. M0 closed under the user's
[approved feasibility decision](decisions/0002-m0-stem-runtime.md). The failed
4.095-second live-stem service p99 target remains a mandatory M2 blocker before
a first usable release.

The decoder uses system libsndfile, already exercised by the earlier reuse
probe. The standard library has no audio decoder; using libsndfile keeps this
path independent of Qt. The laptop has version 1.2.2, with package license
`LGPL-2.1-or-later`. Install `libsndfile` on Arch or `libsndfile1-dev` on Ubuntu;
CI includes the development package.

This first slice accepts nonempty, regular local files with stereo 48 kHz
audio. It preloads at most 64 MiB of float PCM, about 174.8 seconds, before
opening the stream. Unsupported geometry, excessive decoded size, decoder
errors and nonfinite samples fail before playback. There is no resampling yet,
so the earlier 44.1 kHz listening files are not inputs to this path.

The PCM owner outlives the renderer and stream. Rendering copies complete
stereo frames, fills silence after EOF and advances the output sample clock.
Source position clamps at EOF. An owner-thread seek changes source position
without resetting that clock; the probe applies its starting frame before
streaming. Runtime UI transport needs a later command handoff. The callback
does no decoding, file I/O, allocation or locking.

```sh
cmake -S . -B build/dev -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build/dev --parallel 2
ctest --test-dir build/dev --output-on-failure
build/dev/conflux-audio-probe --input /path/to/stereo-48000.wav --seconds 10 --start-frame 24000
```

`--input` and `--tone` are exclusive. Without either, output remains silence.
The report includes decoded frames/bytes, decode time, initial/final source
position and EOF alongside the existing callback and graph-position counters.

All five CTest entries passed. The new audio-file test writes independent
asymmetric PCM16 and float WAV fixtures, checks decoded values and channel
order, compares callback partitions across EOF, and exercises seeks, separate
clocks, byte budgets and invalid input. Six temporary CLI checks verified
invalid combinations and frame values fail before PipeWire initialization.

The laptop check played a generated two-second stereo pattern below −80 dBFS
from frame 24,000, then rendered EOF silence over a 10.053-second stream. All
six audio fault counters were zero across 1,868 callbacks. Callback p99.9's
histogram upper bound was 41 µs; maximum was 41.779 µs. A separate 2.034-second
default-silence check also recorded six zero fault counters. Both negotiated
48 kHz stereo and a 256-frame graph quantum. The
[saved verification](benchmarks/data/m1-entry-2026-10-17/verification.json)
binds the source files, binary and generated input hashes; the audio fixture
is not stored in Git. The build used the recorded working-tree source hashes
on top of signed M0 closure commit `0c33fa2`.

This establishes file decoding and shared rendering. It does not qualify
physical audio latency, musical playback quality or sustained M1 performance.
Two decks, longer-file streaming, transport/jog controls, mixing, cue routing,
gain/meters, stereo recording and the sustained playback run remain M1 work.
