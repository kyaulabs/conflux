# M1 manual audio foundation

M1 is complete within its tested manual-audio scope on 18 October 2026.
Its Qt Quick window provides two local-file decks, with bounded file preparation
and read-ahead, play/pause, temporary CUE, seek, positional jog, independent
master/headphone mixes, peak/RMS meters and live stereo recording. The live
adapter uses 5 ms ramps and replaces sources within the same output session.
The window and headless probe use the same render core. The 30-minute quiet
two-deck audio/UI/recording soak passed, and the user accepted the current test
and recorded-WAV playback on speakers. Physical headphone isolation remains
unverified. The current view
follows the CDJ-3000 deck layout and central four-channel mixer arrangement in
the [control inventory](cdj-controls.md).
M0 closed under the user's
[approved feasibility decision](decisions/0002-m0-stem-runtime.md). The failed
4.095-second live-stem service p99 target remains a mandatory M2 blocker before
a first usable release.

The decoder uses system libsndfile 1.2.2 (`LGPL-2.1-or-later`) and libsamplerate
0.2.2 (`BSD-2-Clause`), both exercised by the earlier reuse probe. The standard
library provides neither codec decoding nor a resampler. Install `libsndfile`
and `libsamplerate` on Arch, or `libsndfile1-dev` and `libsamplerate0-dev` on
Ubuntu; CI includes their development packages. Conversion uses one persistent
`SRC_SINC_BEST_QUALITY` state across bounded blocks, following the
[library's callback API](https://libsndfile.github.io/libsamplerate/api_callback.html).

Nonempty regular local files may contain mono or stereo audio at 8–192 kHz.
Preparation produces stereo 48 kHz float PCM; stereo 48 kHz bypasses conversion
without changing sample bits, and mono expands to identical left/right signals.
Converter output is neither clipped nor normalized, and its actual produced
frame count determines duration. Unsupported geometry, excessive normalized
size, decode errors and nonfinite samples fail before installation.

The manual window prepares at most 256 MiB of normalized PCM per track,
about 11 minutes 39 seconds, in an anonymous temporary file under the app's
cache directory. This describes the qualified M1 implementation; the
[M2 preparation cache](M2.md) now persists validated source PCM between loads.
The M1 temporary file's name is unlinked immediately; descriptor ownership keeps
it alive until readers and the prepared owner close. On this laptop the app
cache is on ext4, whereas `/tmp` is tmpfs. Headless preparation defaults to the
system temporary directory unless a spool directory is supplied. Old A/B and
a newly prepared replacement can coexist, bounded at 768 MiB of temporary
storage. Filesystem page cache is separate from the application's fixed PCM
buffers; temporary storage is not a promise of zero RAM/cache use.

Each active file reader owns a 1 MiB PCM cache, with 32 slots of 4,096 stereo
frames, filled by its background worker. The callback copies only published
blocks through fixed render scratch. Seeks and CUE returns change an epoch;
stale completions cannot supply audio from the previous position. Missing data
fades only that deck to silence, holds its source cursor, advances the output
clock and healthy peer, and increments starvation telemetry. The UI shows BUFFERING
or a current READ ERROR. Error history remains separately recorded. Initial
readers prime before output starts, off the GUI thread; new seeks can briefly
require re-priming.

The headless probe retains bounded in-memory input, at most 64 MiB of final
stereo 48 kHz PCM per deck. It accepts the same source geometry and conversion
but is not the long-file playback adapter. All owners/readers outlive render
access; stream teardown precedes worker joins and descriptor release. The
command-line probe starts loaded decks playing; the manual window installs each new file
paused at frame zero and unity deck gain. Decks have independent source
positions and requested play/pause state.
Pause holds a deck's source position; seek preserves its play/pause state.
Each deck renders silence after EOF and clamps its source position there.
EOF does not change the playing request; seeking back resumes a deck whose
request is still playing. The output sample clock advances for every valid
output block, including silence, and does not reset on a source seek.

Deck and master gains are linear, finite values in [0,1], initially one.
The renderer sums the two float PCM signals using double intermediates for
gain products, addition and master scaling. Conversion back to float saturates
only outside the finite float range. Ordinary values above ±1 remain, so the
sum can clip downstream. There is no limiter or automatic normalization.
The live adapter configures 240-frame linear ramps, 5 ms at 48 kHz, for deck,
master and cue gain, headphone selection and transport discontinuities. Play,
pause, seeks, jog, CUE, EOF and data loss/recovery transition from the last
stereo value toward the new source or silence. Source positions still follow
the transport rules above; a decay does not consume paused or unavailable
source frames. The headless default remains zero-length ramps for exact
sample comparisons. The user accepted the current speaker test without
reported clicks or playback issues.
Invalid deck indices, unloaded-deck commands, out-of-range
seeks and invalid gains leave renderer state unchanged.

Jog is positional search through the bounded command queue. Clockwise dragging
moves two source seconds per revolution; counterclockwise dragging moves back.
Focused Right/Up or Left/Down keys move by ±480 frames (10 ms), as does each
wheel notch. Shift changes the step to ±48,000 frames (one second). Positions
clamp to the source boundaries. Jog preserves requested play/pause and the
stored cue, and cancels temporary preview like seek. It does not implement
scratch, temporary pitch bend, speed adjustment or brake processing.

Mixer CUE selects either deck for the independent headphone bus. It takes the
source before channel and master gain, then applies its own CUE LEVEL in [0,1].
Selection does not start a paused deck; both buses follow the same transport,
including temporary CUE audition. Each source advances once per output frame
while contributing to either or both buses. Master gain, channel faders and
headphone gain do not change each other's signal path.

The A/B meters show stereo peak and RMS after transport transitions and before
channel gain. Master and cue meters show their respective post-gain signals. The display spans
−60 to 0 dBFS, with separate peak markers and RMS fills; hovering gives numeric
values. OVR indicates cumulative samples above ±1 in the current render
session. A new session resets those counts. Cue metering describes the internal
mix even when its physical output is disabled; CUE UNROUTED remains visible.

The manual adapter uses one `pw_filter` with four mono float output ports:
master left/right and cue left/right. Automatic linking is disabled. The
adapter owns explicit links to two distinct playback ports per pair, with
four distinct destinations required for enabled cue. This supports a
four-channel sink on one interface or two stereo sinks in software. PipeWire
handles device clock adaptation; separate physical clocks, DAC alignment and
long-term drift have not been verified with hardware.

Open AUDIO / REC and refresh ports before selecting outputs. An inactive,
unlinked discovery filter allows configuration before a track is loaded and
after output failure. Empty master selections use the default sink's FL/FR
pair at session start; empty cue selections disable cue. Only master uses the
default. Explicit choices bind current node/port IDs and serials, so removal
or identity reuse requires refresh and reselection. A missing cue pair stays
muted while valid master output continues. A lost master stops output; it does
not select an alternate sink. Applying outputs briefly stops the session and
restores its exact stopped transport state. The UI requires recording to stop
before applying outputs.

The engine accepts only a 48 kHz graph clock. A different graph rate mutes
output and reports an error rather than interpreting graph frames at the wrong
rate. This is separate from preparing source files at other sample rates.
Output discovery and recovery do not change system defaults or power settings.

RECORD MASTER writes the post-master bus to a new stereo 48 kHz float WAV;
headphone cue is excluded. Enter an absolute `.wav` path. Opening runs off the
GUI thread and exclusively creates the target, so an existing file is never
overwritten. At a callback boundary, the render owner attaches a borrowed
writer and copies PCM into its preallocated single-producer queue. A background
thread performs file I/O. Stop detaches at a callback boundary and acknowledges
the writer's last possible use before a worker drains, joins and closes it.
The window reports Starting, Recording, Stopping, Finalizing, Complete or
Failed, with the path, captured/saved duration and any error.

Successful source replacement keeps the same filter, output clock and writer,
including its accepted PCM prefix. The render owner fades and swaps only the
target deck; peer audio and post-master recording continue through the shared
output callbacks. This software path does not establish physical output
continuity. Audio settings still rebuild output and require recording to stop
first. Queue overflow, nonfinite input, the bounded WAV size limit or a storage
error terminally fails recording;
playback can continue. The accepted prefix is retained, though a disk error
can leave fewer written than accepted frames. Closing quiesces audio before
joining pending recorder open/finalization work. Blocking storage operations
have no hard cancellation deadline.

Renderer state belongs to the render thread. A separate single-producer,
single-consumer `TransportQueue` holds 32 commands in fixed storage using
lock-free atomics. A full push or empty pop fails immediately. The control
loop enqueues commands; the callback drains at most 32 before rendering a
valid nonempty block and records bounded receipts. Reporting reads those receipts
after the stream stops. The callback does no decoding, file I/O, allocation
or locking.

```sh
cmake -S . -B build/dev -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build/dev --parallel 2
ctest --test-dir build/dev --output-on-failure
build/dev/conflux-audio-probe --input /path/to/deck-a-48000.wav \
  --input-b /path/to/deck-b-48000.wav --seconds 5 \
  --start-frame 0 --start-frame-b 0 --gain-a 0.5 --gain-b 0.5 \
  --master-gain 0.5 --controls /path/to/controls.txt
```

`--input` loads deck A; `--input-b` optionally adds deck B. Both `--input-b`
and `--controls` require deck A.
`--input` and `--tone` are exclusive. Without either, output remains silence.
Starting frames and deck gains require that deck's input. The report includes
each deck's decoded frames/bytes, decode time, initial/final source position,
requested playing state, gain and EOF. It also reports master gain, submitted/
applied/rejected commands and receipts at output-frame boundaries alongside
the existing callback and graph-position counters.

A control script is a regular local file of at most 16 KiB with at most 32
nonempty rows. For example, `controls.txt` can contain:

```text
0 a gain 0.5
500 b pause
1000 a seek 0
1500 b play
2000 master gain 0.5
```

Rows use `milliseconds a|b|master action [value]`. Deck actions are `play`,
`pause`, `seek` with a source-frame value, and `gain` with a value in [0,1].
The master accepts only `gain`. Times are nonnegative milliseconds from entry
to the streaming state, in nondecreasing order, and must precede the requested
`--seconds` duration. Extra fields and commands for unloaded decks are rejected
before PipeWire initialization. The main loop checks due rows every 100 ms;
the render thread applies queued actions at a following callback boundary.
Receipts identify that output frame. This is coarse wall-time scheduling,
without a sample-exact wall-time or click-free transport guarantee.
The probe fails if it stops before every planned action is applied; actions
near the stream's end can remain incomplete.

Run `build/dev/conflux` for the performance window. Select a deck's Browse
control or Library, enter an absolute local file path and select Load A/B. File decoding runs in one QtConcurrent
job while existing playback continues; a second load is rejected until preparation
and retirement finish. A decode error preserves both decks. A second background
stage primes the new reader before publication. If a session exists, loading
an empty deck or replacing a loaded one keeps that session. The render owner
pauses and fades the target, swaps its source, then acknowledges the old
reader's last use. The peer keeps its playing request, cue, gains, headphone
selection and any held preview while its source advances normally. The new
target starts paused at source/cue zero, unity gain and headphone cue off.

Only the target's transport, jog, CUE press and channel controls are gated
while its handoff is pending; physical CUE release, peer and global controls
remain available. The name, duration and overview commit together with the
matching source-generation snapshot. Target controls then resume while old
reader cleanup finishes off the GUI thread. Load remains busy until that
retirement completes. Preparation, priming and reader destruction stay outside
the callback. First load creates a session; explicit output settings rebuild
it. Those new sessions start their output clock and telemetry at zero, whereas
source handoffs retain the shared output clock and cumulative diagnostics.

The GUI never reads live renderer fields. A PipeWire thread loop consumes the
same 32-slot command queue and publishes fixed-size state snapshots through
a separate 32-slot queue. The GUI polls every 50 ms. When snapshot storage is
full, the callback drops telemetry and continues audio; later snapshots carry
cumulative state. Normal window playback has no 32-action lifetime limit.
The callback does no decoding, Qt calls, file I/O, allocation or locking.
Output readiness and errors are polled without blocking the GUI for a startup
wait. Closing first stops audio, requests cooperative preparation cancellation,
then joins preparation, installation and retirement workers before releasing
their owners.
Cancellation is checked between bounded reads, conversion, writes and overview
scans; it cannot interrupt an individual blocking filesystem/codec call.

The live adapter also records fixed execution histograms and available SPA
driver-clock observations. Percentile summaries are computed only after each
session stops; reports keep sessions separate rather than averaging or merging
their percentiles. Graph position, quantum changes, discontinuities and xrun
recovery flags are accompanied by capability information. An unsupported flag
is unavailable, not an observed zero. These counters do not measure scheduler
lateness, physical latency or separate-device drift.

Each loaded deck starts with a temporary cue at frame zero, including leading
silence. While paused away from that point, CUE stores the exact render cursor;
a later press at the point auditions while held. CUE during playback returns
to the stored point and pauses. Releasing an audition returns there and pauses;
pressing PLAY during audition keeps the current cursor and latches playback.
PAUSE or a source seek cancels audition at the current or requested cursor,
leaving the stored cue unchanged. EOF is a valid cue. There is no silence scan,
quantization, persisted cue memory or Hot Cue implementation. The
[control inventory](cdj-controls.md) distinguishes the manufacturer reference
from CONFLUX's explicit release and latch policies.

CUE uses the existing bounded command queue. The GUI retains a release that
cannot fit and retries it before later controls. Pointer and focused keyboard
holds end on release or cancellation; key auto-repeat adds no commands.
Acknowledged snapshots drive the cue indicator and CUE PREVIEW labels.
Stopping the stream drains accepted commands and clears held audition before
capturing final state. Replacing a file resets its cue to zero, preserves the
peer's stored cue and held preview, and clears the target's held gesture. A
full session stop or output rebuild clears held audition. The headless probe's
command script syntax remains play/pause/seek/gain; it does not expose CUE actions.
